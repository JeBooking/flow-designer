# 诊断流程用户手册

[English](USER-GUIDE.md) · [项目说明](../README.zh-CN.md)

本手册面向将现有 Python 工程接入诊断流程的工程师。真实执行由 Flowable 调度、单独启动的 Python worker 调用业务函数；也可独立导出待补业务的离线 Python 骨架。

## 1. 先选择使用方式

| 入口             | 用途                                       | 是否执行业务 Python                        |
| ---------------- | ------------------------------------------ | ------------------------------------------ |
| Python 项目      | 登记工程、发现接口、连续会话调试           | 点击调用时真实执行所选接口                 |
| 开启结构模拟     | 观察 BPMN 令牌动画                         | 否；不验证 Python、数据或业务判断          |
| Flowable 执行    | 部署、启动真实流程、查看结果和处理人工等待 | 由 worker 调用绑定接口                     |
| 导出 Python 骨架 | 生成离线工程，供工程师补业务               | 默认采集/判断/动作未实现，运行时转人工兜底 |

骨架不会自动执行图上保存的外部模块绑定；Flowable worker 才负责这些绑定。登记工程不会自动启动 worker。
结构模拟使用 BPMN 动画规则，也不会验证诊断的是／否结果或串行成功暂停规则。

## 2. 启动与登记已有工程

在仓库根目录分别运行：

```powershell
python backend/server.py
pnpm dev
```

打开 Vite 输出的地址。前端 `/api` 默认转发到本机 `127.0.0.1:8765`。也可先 `pnpm build-only`，再通过后端访问 `http://127.0.0.1:8765/vue-bpmn-designer/`。

点击顶栏 **Python 项目**：

1. **项目目录**：已有工程根目录，如 `D:/equipment/diagnostics`，支持绝对路径或相对本仓库根目录的路径；无需复制工程。
2. **入口模块**：可导入名称，如 `machine.api`，不是文件路径 `machine/api.py`。
3. **Python 解释器**：已有虚拟环境的 `D:/equipment/diagnostics/.venv/Scripts/python.exe`；留空使用后端解释器。依赖须已在所选环境安装。
4. **工厂**（可选）：类名或工厂函数名，如 `Device` 或 `create_session`。留空沿用普通模块函数；填写后展示对象的公开绑定方法，`self` 不作为输入。
5. 可选填写显示名称，点击 **接入项目**。

程序读取函数、签名和文档。有 `__all__` 时展示其导出函数（含重导出），否则展示入口模块自身定义的公开函数：

```python
# machine/__init__.py，也可将 machine.api 登记为入口
from .sampling import inspect_voltage
from .actions import reset_device

__all__ = ['inspect_voltage', 'reset_device']
```

所选解释器以工程根目录为工作目录，并将工程的 `src/`、根目录及父目录加入搜索路径。修改代码后刷新接口；移除登记不会删除工程文件。登记保存在 `backend/.local/projects.json`，Flowable worker 也会读取。

可先使用[设备会话示例](../backend/examples/session_project/README.zh-CN.md)：目录填写 `backend/examples/session_project`，模块 `device_session`，工厂 `Device`。选择接口，只按签名填写实际输入。在同一调试会话依次调用 `collect`、`restore`、`verify`：采集返回原生 `Reading` 对象，恢复后的复核返回 `True`，对象及设备状态在会话内保留。点击 **重置会话** 从初始状态重新开始。调试会真实执行 Python，但不运行整张图，应先选择安全接口。默认超时 120 秒，可用 `python backend/server.py --timeout 600` 调整。

登记类时只检查方法，不创建实例，因而支持必填构造参数；实际创建会话时按启动输入的同名变量或默认值初始化。工厂若有返回类的类型注解，也可免调用发现。无返回类型注解的工厂会用默认参数临时创建对象发现接口；有必填参数时须补上返回类注解。

## 3. 简单画图与填写内容

从 **开始 → 排查 → 结论 → 处置措施 → 问题解决** 开始，再增加“否”分支或上升路径。可载入“并行排查与依赖”示例；载入会替换画布，先导出需保留的流程。旧示例可能需按当前规则迁移。

选中节点，在右侧填写名称和详细内容。名称留空时根据内容与节点尺寸生成摘要，手动名称保留。排查还须填写查看数据、获取方法、判断方法和参考文件；结论需要内容，排查动作需要动作内容。排查负责判断，动作负责执行，结论记录文本，问题解决/上升表达结果。
常规中的“节点类型”为只读，即使名称留空也能识别节点类型。

排查出口选择“是”或“否”，也可将连线命名为“是/否/yes/no”，含义应与判断方法一致。每组可有多条出口，也可只具备其中一组；无匹配出口时记录该思路失败。排查不能直接连接处置措施，先经过结论；排查动作后接排查。校验会报告非法连接和缺失内容，允许先保存草稿。

流程属性选择并行或串行：并行同时启动同组思路，失败仅结束自身；串行按连线 `diagnosisOrder` 升序（同值按定义顺序）尝试，失败后继续队列，成功且有剩余思路时暂停等待“继续/结束”。合流每次到达都继续，不自动等待其他思路。循环须有可达的终止出口。

参考文件可为图片、PDF、文本、音视频或其他类型，单个最大 50 MiB。Flowable compile/start 的请求总量上限为 70 MiB（包含 Base64 与 JSON 开销），多个大附件须控制合计大小。预览能力由浏览器决定；其他类型通过 Windows 本机服务交给本机软件打开，须系统已有相应软件。文件名与内容随流程保存；导出通用项目时资源位于 `assets/`，主 JSON 仅记录相对路径。
无默认关联时会弹出系统软件选择器；脚本和快捷方式始终选择查看软件。本机打开的是临时副本，外部修改不会自动写回项目，修改后需重新选择文件。

## 4. 绑定现有接口与自动匹配变量

选中排查的 **执行与人工判断** 或动作的 **接口绑定**，选择已登记的模块、工厂（若使用）及方法/函数；接口会显示签名，也可手动输入可导入名称。工作主题通常留空使用节点 ID，同一流程内不得重复。

结论只记录文本时无需绑定；问题解决和上升不绑定业务函数。动作支持无参数和返回 `None`。判断应放在排查，返回 `True`/`False`、`yes`/`no` 或 `{"next":"yes", ...}` / `{"next":"no", ...}`。兼容出口连线 ID 的返回值选择其所属整个分组，不是仅该条线。不要依赖普通数字或字符串的真假性。

worker 按签名依次匹配：旧版显式映射（若存在）、同名流程变量、上游结果中唯一的同名字段、函数默认值。无参数直接调用，支持位置专用参数和 `async def`。缺失或来源不唯一会报告具体参数名，不猜测数据。

例如 `inspect_voltage(device_id, threshold=24)`，添加名为 `device_id`、值为 `M01` 的启动数据，即可传入设备号并采用默认阈值。原始返回值在 Python 会话内按 **节点 ID** 保存；以该节点 ID 为名的后续参数取得完整原对象，包括非 JSON 对象。返回 `{"next":"yes","voltage":22.6}` 时，后续 `voltage` 参数也可匹配唯一同名字段。两个结果都含 `voltage` 则有歧义，应使用明确的业务字段/入口包装函数；顶层同名变量优先于结果字段。

已有接口若只返回原始数据，可由工程师增加一个薄入口，复用原采集方法并适配是/否协议（下例假定返回数值）：

```python
from machine.sampling import read_voltage

def inspect_voltage(device_id, threshold=24):
    voltage = read_voltage(device_id)
    return {'next': 'yes' if voltage < threshold else 'no', 'voltage': voltage}
```

将它保存为工程根目录 `workflow_api.py`，登记模块 `workflow_api`，在排查绑定 `inspect_voltage`。根据真实返回类型修改解析与判断，不需要搬迁原工程。

无需在面板填写代码或参数表达式；更换接口会清除旧映射。旧映射继续兼容 `$节点ID.字段`、`$变量名`、`$`（全部变量）及 `$$`（转义美元符）。

已有状态型工程可直接登记现有类。同一流程的同一工程使用一个常驻隔离 Python 子进程，按登记的解释器和工作目录创建一次实例。方法照常访问内部属性，不要求用户重复填写。普通模块函数仍兼容，其模块全局状态也在该流程的子进程内保留。不同流程使用独立进程和对象；同一实例被并行方法访问时，线程安全由业务工程负责。

Flowable 负责分支调度、人工等待与历史，Python 保存原始对象和节点结果。Flowable 只接收可 JSON 化的展示投影；非 JSON 对象显示含 `pythonType`、`representation` 的说明，`repr` 不会替代原对象传给下一方法。人工回退是在当前实例上重跑方法，不回滚内部状态。

原生引用只在同一工程子进程内有效，不同工程间不能直接传递。worker 观察到流程结束后释放其会话；失败会话保留供检查。

设备示例的合法链条是：开始 → 入口排查 `ready`（是）→ 排查动作 `collect`（节点 ID 为 `reading`）→ 排查 `is_low`（是）→ 结论 → 处置措施 `restore_and_verify` → 问题解决。处置在完成前进行异步复核，失败则抛出任务错误。本例只演示恢复思路，可不连接 `is_low` 的“否”分组，或另行设计符合规则的结论/结果路径；仍遵守排查不能直连问题解决、处置措施不能回连排查的既有规则。

## 5. 真实部署与执行

需要 Java 21、Maven 3.9，以及可安装官方客户端的 Python 环境。首次准备：

```powershell
# 在 flowable-runtime 目录
mvn package
java -jar target/diagnostic-flowable-1.0.0.jar

# 在仓库根目录；也可直接使用已有业务虚拟环境
python -m venv backend/.local/venv
backend/.local/venv/Scripts/python.exe -m pip install -r backend/requirements-flowable.txt
```

若 Maven 依赖缓存不齐，但已有可执行 jar，可用 `scripts/rebuild-flowable-local.py` 从其依赖离线重编 Java 与资源；参数见脚本 `--help`。标准构建/发布仍使用 `mvn package`。

保留第 2 节的后端与前端运行。Java 默认地址 `http://127.0.0.1:8080`，示例账号 `diagnostic / local-demo`。代理和 worker 使用相同的 `FLOWABLE_URL`、`FLOWABLE_USER`、`FLOWABLE_PASSWORD`；部署环境配置自己的认证与访问控制。

1. 打开 **Flowable 执行**，点击 **导出执行包** 并解压：`source.bpmn` 是编辑快照，`workflow.bpmn20.xml` 是引擎定义，`bindings.json` 是接口绑定。不要用引擎定义替换原图编辑。
2. 使用装有官方客户端的环境启动 worker：

   ```powershell
   backend/.local/venv/Scripts/python.exe backend/flowable_worker.py D:/exports/bindings.json
   ```

   默认读取 `backend/.local/projects.json`，按模块/工厂选择对应登记，业务调用使用登记解释器及工程工作目录；业务依赖安装在该环境即可。可用 `--registry D:/config/projects.json` 指定其他登记文件。未登记的旧模块可继续用可重复的 `--project D:/equipment/diagnostics` 提供备用根目录，此时使用 worker 自身解释器。

3. 在抽屉填写启动表单：自动读取已登记会话类/工厂的初始化参数，可选值留空使用默认值；其他启动数据通过添加名称/值行填写，如 `device_id` = `M01`。普通方法参数仍可由上游结果自动匹配，不会全部当成初始输入要求填写。使用内置示例时从下拉框选择示例场景，再点击 **部署并启动**。折叠的 **高级初始变量 JSON** 可选择开启以替代表单，默认 `{}`；例如 `{"device_id":"M01"}` 仅作为高级替代方式。
4. 点击 **刷新执行结果** 查看实际节点、结果、失败记录、人工等待和执行详情。结果含 `chartSvg` 字符串时可显示 SVG 图表，任意本机路径不会自动变成图表。
5. 更改绑定、连线、分组或顺序后重新导出并启动对应 worker，旧实例仍需旧 worker。不要让业务配置不同的 worker 订阅同一主题。业务代码更新应在启动流程前安排好，重启 worker 会丢失其活跃 Python 会话。

worker 未运行时，自动任务会等待，不会自行调用 Python。接口异常属于任务失败，在 Flowable 执行中刷新结果并展开失败详情，即可查看原始 Python traceback，worker 日志可补充上下文。重试可能重复调用，机台动作须按业务需要保证幂等。

Python 内存没有自动检查点或重启恢复。worker/子进程重启后，继续旧流程会明确报告会话丢失，不会悄悄重建另一台设备实例。Flowable 的历史及展示变量无法还原原对象；按实际设备状态妥善处理后，再启动新流程。

同一 Flowable 服务的相同执行包/主题只启动一个 worker 协调器，它可同时处理多次排查，各流程使用独立工程子进程。同机重复启动会明确报错；本机锁不能协调不同机器，因此跨机器也须保持单协调器。旧的无状态函数兼容不代表多个竞争协调器可以共享原生对象或安全水平扩容。

Flowable 编译目前支持一个顶层流程、一个普通开始事件和本项目诊断节点；子流程、复杂事件、普通并行网关等会拒绝。条件表达式/默认分支也拒绝，应使用排查是/否结果。离线骨架支持范围更宽，不能据此判断 Flowable 可部署。

## 6. 人工判断、组件兜底与回退

排查打开 **人工判断／确认** 时，不绑定 Python 可直接等待人工；绑定后先执行接口，再等待复核。开关只出现在排查上，动作的离线“完成确认”是另一机制。

已有业务判断可使用组件，未实现时主动请求人工，无需打开上述开关：

```python
from diagnostic_components import decision

@decision(instructions='对照曲线确认电压是否低于额定值')
def inspect_voltage(device_id, threshold=24):
    raise NotImplementedError('由工程师接入真实采集与阈值判断')
```

也可继承 `DecisionComponent` 实现 `decide`。仅组件未覆盖实现或明确抛出 `NotImplementedError` 才产生 `HumanDecisionRequest`；普通函数直接抛出该异常不会自动兜底。`pass` / 返回 `None` 不表示未实现，其它异常仍是失败。请求对象应直接返回，不要自行 JSON 化；支持同步/异步。worker 提供组件导入路径，独立运行时需自行加入本仓库 `backend`。

刷新抽屉，在人工等待中查看数据、判断方法和选项，选择是/否后继续。上升先等待复核，确认后结束；串行成功且有剩余队列时可继续或结束。

排查或上升的人工等待中，可选择此前实际执行过的节点，填写原因和可选复查输入变量，点击 **回退重查**。回退保留历史、旧值和原因，清除需重算结果并重新执行；不会撤销机台动作，动作可能再次运行。当前节点、未执行节点和已结束实例不可作为任意回退入口；运行中的自动节点不提供暂停介入。

## 7. 保存、移动和导入

- **导出诊断项目**：ZIP 的唯一主定义为版本 4 `workflow.json`，资源独立存放。保留内容、绑定、依赖、分支、顺序和模式，省略布局/尺寸/颜色/字体。
- **导入项目目录**：选择解压目录，同时读取 JSON 与相对资源。单独导入 JSON 若提示缺失资源，改用目录导入；自动排版，无需重新上传已有附件。
- **导出完整 BPMN**：完整编辑快照，适合保留布局继续编辑。
- **导出 Python 骨架**：复用同一 JSON 与 `assets/`，增加模块、示例输入、说明与实现索引，不额外保存 `source.bpmn`。
- **Flowable 导出执行包**：为引擎编译，与通用项目不同，包含第 5 节三个文件。

移动通用项目时整个目录一起移动，勿改为绝对资源路径。旧 JSON 可导入，旧分支缺少明确是/否时须补充。BPMN 扩展使用 `flowable:` 前缀，通过编辑器修改支持撤销/重做。

## 8. 工程师补全离线 Python

解压到新目录，使用 Python 3.10+（仅标准库）：

```powershell
python runner.py
python runner.py --data inputs.json --no-images
```

先读 `IMPLEMENTATION.md` 按节点 ID 定位函数。每处注释标明节点 ID/类型/名称/完整内容、输入输出、出口与文件调用关系。`node_N` 会随导出顺序变化，应按 `HANDLERS` 的节点 ID 迁移实现。

| 文件                   | 待补业务与默认行为                                                           |
| ---------------------- | ---------------------------------------------------------------------------- |
| acquisition.py         | 原始采集；未实现时展示采集方法，输入文本/JSON 或 `@JSON文件路径`             |
| parsing.py             | 解析、校验、单位转换；默认原样返回                                           |
| display.py             | 业务图表；默认输出数据与参考路径，尝试浏览器打开，`--no-images` 禁用自动打开 |
| diagnosis.py           | 自动判断；未实现时展示方法并人工选是/否                                      |
| actions.py             | 真实动作；未实现时手工完成后须输入 `yes` 才继续                              |
| routing.py / runner.py | 分组、依赖、调度、历史、失败和恢复；通常无需修改                             |

调用链为 `runner → acquisition → parsing → display → diagnosis → routing → 后继`，动作由 `runner → actions` 调用。可在函数中显式导入已有业务包，并确保当前 Python 能导入它。仅明确的 `NotImplementedError` 占位转人工，其它异常停止；解析和展示错误不转为人工成功。

复制 `inputs.example.json` 为 `inputs.json`，替换实际值，只保留已知节点。`--data` 或 `run(supplied={节点ID: 原始数据})` 跳过对应采集，继续解析/判断。`Context.ask/show` 可替换界面，`context.data[节点ID]` 保存 `raw/parsed/result`。串行暂停返回 `state`，用 `run(..., resume=state, success_action='continue'|'finish')` 恢复。默认最大 1000 步（`--max-steps`），自动函数的超时自行管理。

离线支持普通嵌套子流程和排他选择，条件文本只展示不执行。结果包含问题解决、上升、跳转、失败或串行暂停；跳转是交接，不代表目标链路已运行，须另行对接。重新导出到新目录，按 ID 迁移，避免覆盖业务代码。

## 9. 常见问题

| 现象                 | 检查                                                                |
| -------------------- | ------------------------------------------------------------------- |
| Python 项目连接失败  | 后端是否运行，端口与代理是否匹配                                    |
| 找不到接口           | 根目录、入口模块、`__all__`、解释器与依赖，修改后刷新               |
| 模拟能走，实际没结果 | 结构模拟只播放令牌；检查 Java、后端、匹配 bindings 的 worker 和主题 |
| 参数缺失/歧义        | 签名、初始变量、已执行上游结果，避免同名字段来源冲突                |
| 导出被拒绝           | 按节点 ID 修正必填项、分支、终止出口或不支持结构                    |
| 无法路由             | 排查返回明确是/否，不能用 `None` 或普通数据代替判断                 |
| 文件打不开           | 完整导入目录，确认资源存在和本机有支持格式的软件                    |
| 回退后动作重复       | 回退是重跑，不是撤销；业务动作需处理幂等                            |

技术细节见 [Python 接入说明](../backend/README.md) 和 [Flowable 技术说明](../backend/FLOWABLE.zh-CN.md)。较早示例中的互斥分支/手写参数说明，以本手册的当前分组和自动匹配规则为准。
