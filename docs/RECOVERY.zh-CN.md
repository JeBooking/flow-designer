# 执行监控与业务现场恢复

[English](RECOVERY.md)

## 恢复已有实例的监控

最近监控的实例 ID 和最近十个 ID 会持久保存。刷新页面或重建 modeler 后自动接回最近实例；
浏览器持久化中不保存业务结果。在“诊断执行”输入或选择 ID，点击“恢复监控”，即可查看其他
已有实例并继续其待办。“停止监控”只断开界面，不取消实例。

导入原流程后，后端会比较执行签名。匹配前仍可查看历史和待办卡片，但不显示画布高亮；
修改画布会使关联失效。切换其他 ID 失败时保留已加载的监控；失效或已删除的实例可以停止监控，
然后开始其他执行。

历史请求使用不透明游标和变量修订号，只传输变化的值、新增／完成的活动、删除项及变化的
待办和失败信息。状态不变时轮询间隔从 1.5 秒逐步增至最多 10 秒；提交复核后立即刷新。
游标过期、后端重启或缓存淘汰时自动返回完整快照，已结束实例仍从历史数据读取。

## 声明可恢复的业务状态

Flowable 持久化流程和人工等待；业务检查点额外保存工程明确声明可恢复的 Python 状态。
它与展示投影分开，不从 `repr` 猜测原生对象。接口调试会话仍为临时会话。

没有可变业务全局状态的模块可以声明：

```python
__diagnosis_stateless__ = True
```

声明只针对模块全局状态，不表示工厂实例无状态。需要保存全局状态的模块应提供
`__diagnosis_checkpoint__()` 与 `__diagnosis_restore__(state)` 接口，可为同步或异步函数；
导出的全局状态必须兼容 JSON，恢复不能重放过去的设备动作。

工厂实例和结果中的原生对象需提供同步对象接口：

```python
__diagnosis_stateless__ = True

class Device:
    def __diagnosis_checkpoint__(self):
        return {'count': self.count, 'latest': self.latest}

    @classmethod
    def __diagnosis_restore__(cls, state):
        device = object.__new__(cls)
        device.__dict__.update(state)
        return device
```

如果 `latest` 是原生对象，其类型也需实现这两个接口。编码器保留实例状态和节点结果之间的
共享引用；支持 JSON 标量、字符串键字典、列表和元组。自定义对象的循环引用需要由工程换一种
表示，类型必须属于登记工程。不使用 pickle，不自动重跑构造函数，也不把展示投影还原成对象。
[设备会话示例](../backend/examples/session_project/README.zh-CN.md) 已为 `Device` 和 `Reading` 实现此协议。

设备连接、外部句柄应导出稳定标识和配置，再由恢复接口重新连接。重新连接不能重新发送过去的
处置动作；工程仍需保证声明状态的正确性，以及并行调用时的线程安全。

## 持久化与重启行为

worker 在调用业务前原子记录“动作执行中”。同一会话的全部并发调用结束后，先保存状态和作业
响应，再确认 Flowable 作业。恢复后再次领取同一作业时复用已保存响应，不再调用业务函数；
引擎确认提交后清理对应响应缓存。

当所有工作都在等人工处理时，完整检查点允许空闲业务解释器退出，协调器仍保持订阅。
后端启动后扫描活动定义，重新创建缺失协调器；下一次调用恢复会话和原生引用。
已有作业锁仍遵循 Flowable 锁生命周期，重启不抢占锁。worker 观察到实例结束后清理其本地检查点。

检查点位于 `backend/.local/checkpoints/`，按引擎 URL、执行版本、实例和工程身份隔离。
文件通过临时写入、flush/fsync 和原子替换保存，单份上限为 64 MiB；恢复时校验源码、
Python／依赖环境和原会话 ID。迁移可恢复安装时，应一并保留这个目录和本地引擎数据。

执行面板显示最近一次调用是否保存了可恢复检查点。不支持的状态继续保留活跃解释器，并说明
缺少的协议。动作尚未完成时崩溃、检查点缺失或未完成、代码或依赖改变、恢复接口失败，都会拒绝
自动恢复。此时先确认实际设备状态，再决定怎样继续；在外部动作完成但结果尚未记录的窗口，
任何重启或检查点都无法证明动作的最终结果。显式回退重查仍在当前状态上运行业务代码，可能重复动作。

## 使用预构建 Java 引擎

从相同源码提交的一次成功 **Verification** 运行下载 `diagnostic-flowable-runtime`，把 JAR 和
`.manifest.json` 一同放入 `flowable-runtime/target/`。启动器校验源码和 JAR 哈希，统一文本换行，
不会因为检出时间不同而强制运行 Maven。匹配产物只需 Java 17+、Python 3.9+、Node／pnpm 和
前端依赖；源码构建仍需 JDK 17+ 与 Maven 3.8.8+。不会自动下载未经校验的外部发行物。

`pnpm verify` 覆盖增量历史、监控 ID 持久化、原生检查点引用、等待释放、后端重启和并发复核记录。
